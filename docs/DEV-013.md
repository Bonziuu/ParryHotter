# DEV 0.13: sterowanie, wygląd i walidacja

Ten dokument opisuje aktualny kod. Rozdziały starszych wersji w README są historią.
Aktualna DLL jest **skompilowana przez MSVC** (GitHub Actions, `windows-latest`,
`G1 Release / Win32`, SDK `4ae1fc51`) i zweryfikowana jako PE32 i386 z
identyfikatorem builda. Log z testu `b25528b` potwierdził blokadę rzucania;
poprawka maskowania wejścia wymaga ponownego testu w ZenGin. Analiza i aktualny
stan są w [HANDOFF-DEV013-STAN.md](HANDOFF-DEV013-STAN.md).

Automatyczne pobieranie i instalację najnowszej DLL zapewnia
`AKTUALIZUJ_PARRY_HOTTER.bat`; paczka narzędzi jest publikowana w `dev013-latest`.
Instrukcja: [AKTUALIZACJA-DLL.md](AKTUALIZACJA-DLL.md).

## Sterowanie

| Wejście | Zachowanie |
| --- | --- |
| Mysz | Obrót kamery w poziomie i pionie, ograniczony kąt pionowy |
| WASD / strzałki | Ruch względem kamery, równa prędkość po skosie |
| PPM / spacja | Niski skok 70 cm na natywnej fizyce, bufor 150 ms; bez automatycznego ponawiania |
| 1–6 | Wybór istniejącego czaru |
| 7, 8, 9, 0 | Wybór pustego pola; brak przygotowania i rzutu |
| Przytrzymanie LPM | Przygotowanie różdżki i celowanie |
| Puszczenie LPM | Rzut na namierzonego żywego NPC do 19 m; bez celu anulowanie |
| F10 | Diagnostyka namierzania i impulsów |
| F11 | Przełączanie nowej kamery/ruchu i standardowego sterowania ruchem |

Znak czaru jest związany z górną częścią tułowia NPC, rzutowany na ekran i
delikatnie animowany. Znajduje się przy postaci, a nie na stałe przy celowniku.
Znaki i kwadraty zachowują kwadratowe proporcje w pikselach przy różnych proporcjach ekranu.
Znak wymaga aktywnego LPM i poprawnego celu. Gdy czar nie jest gotowy,
pozostaje przygaszony; jasny znak oznacza gotowość do rzutu.

Ruch i czary korzystają ze wspólnego warunku dozwolonego stanu postaci. Pływanie,
wspinanie, utrata przytomności i sterowanie przez skrypt przerywają przygotowanie;
kamera oddaje wtedy ustawienia natychmiast. F11 zmienia tylko ruch/kamerę, więc
klawisze 1–0 nadal wybierają pola czarów bez natywnego wyboru broni. Konsola Gothica blokuje też WASD, mysz, cyfry i skróty F10/F11 moda. Po pauzie,
wczytaniu lub zmianie opcji należy zwolnić LPM przed ponownym celowaniem.

Prędkości domyślne: bieg i celowanie 540 cm/s. Parametry, przyspieszenie,
hamowanie i sterowanie w powietrzu są w `union/hud/Locomotion.hpp`.
Zależne od czasu wygładzanie/czułość i ograniczenia pionu są w `FreeCamera.hpp`.
Adapter używa natywnych operacji ruchu z kolizjami w krokach do 10 cm; nie wyłącza
kolizji ani grawitacji. Skok wymaga natywnej animacji, kontaktu z podłożem i zwykłej grawitacji.
Jednorazowy impuls daje docelowo 70 cm; natywne kolizje skracają skok pod sufitem.
Po udanym rozpoczęciu skoku adapter nie wysyła w tej samej klatce polecenia biegu
ani stania, które mogłoby zastąpić animację skoku.
Prędkości i zachowanie kamery wymagają oceny w rzeczywistej grze.

## Zbudowanie aktualnej wtyczki na Windows

Wymagane: Git, Visual Studio 2022 z narzędziami Desktop development with C++, Win32
i Windows SDK. Z katalogu projektu:

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_union.ps1
```

Skrypt pobiera SDK Union z dokładnego commita
`4ae1fc51bd962e72ed2a0b1d3da92084517db996`, kopiuje aktualne źródła i nagłówki,
buduje `G1 Release / Win32` z C++17 i zapisuje wynik do
`.parryhotter/build/ParryHotterHUD-G1.dll`. Katalog SDK jest tymczasowy.
W tymczasowym projekcie cytuje ścieżki polecenia aktualizacji wersji, aby spacje
w nazwie użytkownika lub katalogu TEMP nie przerywały budowania.
GitHub Actions uruchamia **ten sam skrypt** przy każdym pushu,
a potem `python -m tools.verify_dll`, który sprawdza nagłówki PE (i386, DLL, PE32),
identyfikator builda, SHA-256 i importowane biblioteki. Ten sam test można
uruchomić lokalnie:

```powershell
py -3 -m tools.verify_dll .parryhotter/build/ParryHotterHUD-G1.dll
```

Pierwszy udany build DEV 0.13 (commit `6df5bca`): 180 736 bajtów,
SHA-256 `55dc462d34d5afad4d64aeb17b1e0421b5c44c43942da3f29838ce7889ba9933`,
importy tylko `Shw32.dll` (SmartHeap, dostarczany z Gothikiem) i `KERNEL32.dll`;
CRT jest linkowany statycznie. Bez Visual Studio DLL można pobrać jako artefakt
`ParryHotter-Union-G1-EXPERIMENTAL` z przebiegu workflow na stronie Actions
(wymaga zalogowania na GitHubie) i podać przez `--hud-dll`.

Nagłówki pluginu nie mogą używać nazw, które SDK Union definiuje jako makra
(`Invalid`, `None`, `True`, `Success`, …; `UnionSDK/utils/Macro.h`).
`tools.check` wymusza dołączenie `union/tests/union_sdk_macros.hpp`, więc taki
konflikt kończy się błędem już w g++, a nie dopiero w MSVC.

Następnie instalacja skryptów, **Reparse Scripts** w GothicStarter_mod i budowa
lokalnego `.mod` przez `ZBUDUJ_MOD_PO_REPARSE.bat`. Pakowanie wybiera lokalną DLL,
jeśli jest dostępna. Alternatywnie można podać `--hud-dll` do `tools.package_mod`.
Każda DLL musi mieć identyfikator `PH_BUILD_013_TEN_SLOTS_PROJECTILE_INPUT_CAST_ANIM`.
Pobieranie starego wydania `hud-dev` zakończy się wyjaśnionym błędem, dopóki nie
zostanie ono zastąpione zgodnym buildem; suma SHA-256 pobrania nadal jest wymagana.

## Rzeczywista postać Harry’ego

Gotowy zestaw `ParryHotter_Harry_Gothic.zip` przechowuje się wyłącznie lokalnie,
poza repozytorium. Nie jest częścią publicznej paczki narzędzi. Instrukcję dla Claude Code, kontrolę sumy i import
opisuje [MODEL_DLA_CLAUDE_CODE.md](MODEL_DLA_CLAUDE_CODE.md). Poniższy opis konwersji
dotyczy odtwarzania lub modyfikowania modelu; instalacja gotowej paczki go pomija.

Potrzebny jest lokalny model HP2 PC `skharrymesh.fbx` i cztery tekstury
`skharryTex0.png`–`skharryTex3.png`, a także referencja szkieletu
`Gothic/ParryHotter-private/GothicHuman.blend`. Alternatywą jest źródłowy
`HUM_BODY_NAKED0.ASC` w danych ModKitu i zgodny importer KrxImpExp.

Przesłane archiwum Harry’ego zawiera FBX 6000, którego aktualny importer Blendera
nie obsługuje bezpośrednio. Narzędzia używają dołączonego OBJ/MTL, zachowują wszystkie
1016 trójkątów (w tym dwustronne powierzchnie szaty), UV i cztery materiały.
Oryginalne macierze wiązania i wagi są odczytywane ze starego FBX: odzyskano
143 kości i wskazanie 35 wierzchołków peleryny. Okulary mają podłączony kanał alfa.
Tekstury są osadzone w prywatnym projekcie PREP, ale jego oryginalny szkielet HP2
nie zastępuje referencji Gothica. Po przygotowaniu modelu nadal potrzebne są
rzeczywiste GothicHuman.blend lub HUM_BODY_NAKED0.ASC ze skórkowaną siatką.

`model_asset.py` przygotowuje scenę, a `blender_visual_first.py` przenosi i
normalizuje wagi, dopasowuje głowę i przypisuje pelerynę do kilku kości tułowia.
Przy zainstalowanym operatorze `export_scene.krxascexp` eksportuje prawdziwy ASC.
Brak eksportera jest jawnie zapisany w raporcie JSON. Stary eksport nie zastępuje
nowego źródła: staging sprawdza daty, geometrię, kości i wagi oraz komplet tekstur.

W tej chmurze zainstalowano przypięty importer i eksporter Kerrax w
`/workspace/.parryhotter-cloud/krx-toolchain`. Prawdziwą referencję ModKitu pobrano
z PhoenixTales/gothic-devkit, commit `0b81c1932d11fd212c877cb8fd4e4a85ab2584de`.
Narzędzia mogą automatycznie pobrać brakujący HUM_BODY_NAKED0.ASC; wymagają
przypiętej sumy SHA-256 i zapisują pochodzenie poza repozytorium. Opcja
`--offline-reference` wyłącza pobieranie w instalatorze i model_asset.

**Rzeczywisty model został przekonwertowany:** 25 kości Gothica, 710 ważonych
wierzchołków, 1016 trójkątów, 35 wierzchołków peleryny. Mapowanie semantyczne
korzysta z oryginalnych wag HP2; różnice pozy i osi kończyn są uwzględnione bez
odwracania dłoni/stóp. Twarz, włosy i okulary podążają za głową; próby obrotu
45°, uniesienia ręki i zgięcia kolana wykonano w Blenderze. To nie jest test ZenGin.

Paczka `ParryHotter_Harry_Gothic.zip` zawiera ASC i cztery tekstury oraz raporty.
Po umieszczeniu jej obok `INSTALUJ_PARRY_HOTTER.bat` instalator używa jej bez
Blendera i bez pobierania źródłowego modelu. Ręczne polecenie:

```powershell
py -3 -m tools.import_harry_bundle --game "C:\Gry\Gothic" --bundle "ParryHotter_Harry_Gothic.zip"
```

Import waliduje cały model i źródła ModKitu przed zapisem, tworzy kopie zapasowe
i rejestruje kostium. Instalator sprawdza zawartość jawnie podanej lub dołączonej
paczki modelu przed wymianą Content. Import modelu obejmuje jedną transakcją
prywatny cache, aktywne modele/tekstury, rejestrację skryptów i kopie zapasowe:
błąd zapisu przywraca poprzednie pliki. Gdy samo przywracanie zawiedzie, narzędzie
zachowuje kopie i podaje ich lokalizację. Pakowanie `.mod` podobnie przywraca
poprzednie archiwum i profil PLAY, jeśli zapis jednego z nich się nie powiedzie.
Następnie wykonaj Reparse Scripts i przebudowę lokalnego
.mod z aktualną DLL. Sprawdzono instalację na odizolowanej kopii prawdziwych
Unified-PL/HUMANS.MDS, w tym powtórzenie bez zmian i zachowanie kopii zapasowej.
Oryginalnych klipów HP2 i fizyki peleryny nie importowano.

## Własne animacje różdżki

Dodano dwa autorskie klipy inspirowane ruchem czarowania z HP PC: przygotowanie
z uniesieniem prawej ręki i lekką pętlą oddychania (43 klatki) oraz skierowanie
różdżki do przodu z powrotem do spoczynku (26 klatek). Oba mają 30 FPS i komplet
25 kości. Globalny korzeń i nogi pozostają nieruchome; grawitację i przesuwanie
postaci nadal obsługuje silnik. To klipy całego szkieletu. DLL dodaje autorski proceduralny cykl nóg podczas
poruszania się z czarem; nie uruchamia natywnego chodu, który blokuje inwestowanie.
Nie stanowi to pełnego zestawu oryginalnych animacji HP2.

Pliki `PH_HARRY_CHARGE.ASC`, `PH_HARRY_RELEASE.ASC` i `PH_HARRY_CAST.MDS` są
opcjonalnym, kompletnym zestawem w paczce modelu. Instalator sprawdza zgodność
macierzy wiązania, hierarchię, wszystkie próbki, nieruchomy korzeń, zamknięcie
pętli i łączenie klipów. Nakładka jest dopisywana tylko w konstruktorze `PC_Hero`,
po `Humans_Mage`. Na starym zapisie konstruktor nie wykona się ponownie.

Wtyczka zachowuje natywne `TransitionToInvest/Cast`, podstawiając sześć uchwytów
z unikatowymi nazwami `*_PH_*`. Pozwala to użyć tej samej sekwencji dla sześciu
czarów, także tych, które w Gothicu mają tylko fazę Shoot. Nie zmienia animacji
NPC. Niekompletna lub niezaładowana nakładka pozostawia natywne uchwyty.
Przerwanie przywraca tylko nadal posiadane uchwyty i zatrzymuje własne animacje.
Obsługę i kolejność w silniku trzeba jeszcze sprawdzić na końcowej DLL.

Powtórzenie autorstwa na istniejącym przekonwertowanym modelu:

```bash
blender --background --python-exit-code 1 --python tools/blender_casting.py -- HARRY.blend KATALOG_WYNIKOWY
```

Narzędzie wymaga zainstalowanego KrxImpExp i osadzonych tekstur z konwersji.
Ponownie eksportuje zgodny model i tworzy osiem plików źródłowych, projekt
`ParryHotter_CASTING.blend` oraz raport. Waliduje je przed wspólnym zapisem;
nieudany eksport zachowuje poprzedni zestaw. Poprawiono utratę precyzji starego
eksportera dla obrotów bliskich 180°, również w macierzach modelu.

Oba rzeczywiste klipy przeszły ponowny import Kerrax w Blenderze z adapterem
odświeżania zależności i pełnych kluczy początkowych dla starszego importera.
Maksymalna różnica pozycji kości wyniosła 0,00000136 m. Podglądy nie są nagraniem
Gothica. Pakowanie zawiera surowe ASC/MDS; kompilację MSB/MAN i odświeżenie cache
animacji nadal musi potwierdzić gra.

Instalacja usuwa oryginalną głowę tylko u PC_Hero. Wtyczka próbuje zachować wygląd
Harry’ego po zmianie pancerza bez zmiany jego statystyk. Obydwa zachowania trzeba
sprawdzić na końcowym modelu, także po zapisie/wczytaniu i zmianie świata.

## Testy i pozostałe ograniczenia

```bash
python -m tools.check
python -m tools.verify_download
python -m tools.verify_daedalus
```

Pierwsze polecenie uruchamia testy Python, wszystkie przenośne testy C++ i pełną
walidację 15 tekstur HUD. Symulacja adaptera sprawdza zarządzanie wejściem,
przywracanie skal animacji, skoki i wywołania ruchu; nie zastępuje ABI silnika.
GDC korzysta z przypiętych oficjalnych binariów i SHA-256 na Linux/Windows.
Jego tymczasowy DAT z adaptacją C_NPC służy kontroli kodu, **nie instalacji**.

Przed wydaniem potrzebne są próby w Gothic 1:

- Prawdziwa DLL ładuje się z `.mod`; nowa gra i zapis/wczytanie nie powodują awarii.
- Dziesięć pól jest stale widoczne podczas rozgrywki; cztery puste nie zużywają many.
- Znak podąża za NPC przy obrocie kamery i ruchu celu; znika po utracie celu/PPM.
- Przytrzymanie LPM celuje, puszczenie rzuca raz; PPM skacze bez ponawiania.
- Nieudany rzut nie rozpoczyna odnowienia; potwierdzony rzut rozpoczyna je raz.
- Kilka pocisków ma poprawne ofiary i efekty, również po zmianie wybranego czaru.
- Ruch i sterowanie skokiem respektują ściany, sufity, schody i krawędzie.
- Kamera oraz wejście wracają do gry podczas rozmów, menu, pływania i wspinania.
- Harry nie ma drugiej głowy, poprawnie zgina kończyny i zachowuje wygląd po zmianie zbroi.

Sześć czarów nadal używa efektów Gothica. Własne klipy różdżki wymagają próby w grze.
Pełny zestaw animacji HP, unoszenie
głową w dół, peleryna jak w HP2 i ragdoll/obroty Bumbardo nie zostały ukończone.
Dotychczasowy impuls fizyczny nadal wymaga aktywnego natywnego ciała NPC.

## Iteracja sterowania V3 (13.11.2026)

Znacznik logu: `PH_CONTROLS_V3_EVENTS_READY`. Kolejka zachowuje pełne kliknięcia
między klatkami i cel z chwili puszczenia LPM. Wybrany slot HUD i przygotowany
czar mają osobne identyfikatory; puste pola anulują przygotowanie. Szybkie
puszczenie może oczekiwać na gotowość natywnej magii. Cel jest ponownie
sprawdzany przed samym rzuceniem, również po callbackach silnika.

Kamera obniża punkt nad głową przy przysunięciu i pod dachem, sprawdza też
przekrój przy near clip. Ruch używa rzeczywistego przemieszczenia po kolizjach
jako informacji zwrotnej. Spadanie z pozycją czaru ponownie włącza natywną
fizykę; zabezpieczenie penetracji podłoża dotyczy tylko świeżego, bliskiego kontaktu.

Diagnostyka łączy sekwencje wejścia z żądaniami rzutu, loguje inwestowanie many,
przyczyny odmów, fazy skoku i dwie próbki ruchu/kamery na sekundę. Limit logu
wynosi 4 MiB; każda linia jest od razu zapisywana na dysku. Koszty HUD są
odczytywane z aktywnych skryptów. Anulowanie już ładowanego czaru może zużyć
natywną manę; plugin nie wykonuje niepewnych zwrotów.

Scenariusze i analizator logów: [TESTY-STEROWANIA-HP2.md](TESTY-STEROWANIA-HP2.md).
Testy przenośne i kompilacja DLL nie potwierdzają jeszcze zgodności 1:1 z HP2
ani wystrzału wszystkich sześciu czarów w sesji użytkownika.

## Ponawianie rzutów V4

`PH_CAST_V4_INSTANT_WAND_REARM` zastępuje cykl ReadySpell/UnreadySpell
natychmiastowym przygotowaniem natywnej magii. LPM nie kolejkuje wyciągania
broni, a jego puszczenie nie kolejkuje schowania przed wystrzałem. ACTION i UP
są rozdzielone, aby Gothic mógł skasować znacznik poprzedniego rzutu i rozpocząć
następne ładowanie. Nowe pola `lastCast`/`rearm` pozwalają sprawdzić to w logu.

Log V3 potwierdził jeden Flipendo i ujawnił blokadę kolejnych ośmiu żądań.
Test V4 wymaga powtarzania tego samego czaru, także przy krótkim LPM i po
zmianie slotu; nie wystarczy pojedynczy udany rzut po uruchomieniu gry.

## Namierzanie V5

`PH_CAST_V5_BODY_AIM_AVADA_READY`: pomoc obejmuje bryłę NPC z marginesem 12°,
z retencją 16° i łatwym przełączaniem na postać pod kropką. Pozostają zasięg
19 m od gracza oraz sprawdzanie przeszkód. Brak gotowości czaru przygasza znak
zamiast ukrywać przechwycony cel. Logi `aim` rozdzielają brak celu od cooldownu
i odrzucenia przez widoczność.

Krótki klik Avady czeka na natywny status CAST przed zwolnieniem klawiszy
silnika. Przerwanie jej shoot przez skok lub trafienie nie uruchamia drugiego
płatnego ładowania tego samego żądania.
